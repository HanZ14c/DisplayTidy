## API 核对依据

Apple [CGConfigureDisplayOrigin](https://developer.apple.com/documentation/coregraphics/cgconfiguredisplayorigin(_:_:_:_:)) 描述主屏原点、左上角坐标以及系统可能调整请求位置；[CGConfigureOption](https://developer.apple.com/documentation/coregraphics/cgconfigureoption) 描述 `.forSession` 生效范围；[CGDisplayCreateUUIDFromDisplayID](https://developer.apple.com/documentation/colorsync/cgdisplaycreateuuidfromdisplayid(_:)) 提供 UUID 读取接口。

当前 SDK 的 `CGDisplayConfiguration.h` 说明 Complete 返回后事务已失效，因此 Complete 失败后也不重复取消同一事务；仅在完成提交前失败时取消。

普通版和 App Sandbox 版重新构建通过；self-test 覆盖下侧居中正半整数取整、较宽目标屏的负半整数取整、下侧左对齐及布局合法性。新增下侧操作的系统位置提交已于下述快照修复验证中实测。

## 旧快照阻塞修复（当地 2026-10-03 19:39）

旧快照记录随航为主屏、尺寸 1530 × 1147；当前 LG 为主屏，随航为 1349 × 1011。拒绝直接恢复符合保护条件，但原流程同时拒绝所有新移动，导致无法继续使用。

新增「归档旧快照」确认入口，将原文件完整移动至 `RecoveryArchive`，不改变显示器排列。归档后原文件 SHA-256 与归档前一致。尺寸、主屏或屏幕集合不符时继续拒绝恢复，并提供具体差异；已有有效快照时允许连续调整，保留首次移动前的恢复点。

当前普通版实际验证：LG runtime ID 2，主屏 `(0,0,2560,1440)`；随航 runtime ID 4，初始 `(0,1440,1349,1011)`。下侧居中提交到 `(606,1440)` → 直接下侧左对齐到 `(0,1440)` → 恢复到初始 `(0,1440)`，三次提交均 `CGError 0`，重新读取均一致。连续两次移动之间恢复文件 SHA-256 不变；恢复后活动快照移除，旧归档保留。

普通版与 App Sandbox 版构建、自检均通过；损坏文件无损归档、重复归档不覆盖及缺失文件拒绝已通过临时文件自检。本次连续对齐设备测试使用普通版，未重复 App Sandbox 版的设备操作。

## 关系式排列更新（当地 2026-10-03 20:01）

按用户讨论改为只记忆程序设置的下侧左对齐、居中、右对齐关系。移除恢复和归档入口；历史记录中的恢复行为仅描述旧版本。旧快照文件不改动，新版本使用独立的 arrangement.json 保存 UUID 与对齐方式。

普通版和 App Sandbox 版构建、自检通过。自检覆盖三种对齐、尺寸变化重新计算、UUID 相同且运行时 ID 改变、缺失或重复身份、参考主屏变化和 JSON 编解码。尺寸变化是计算自检，尚未修改设备分辨率进行实测。

普通版通过新界面实际操作随航：LG 为主屏 (0,0,2560,1440)，随航 1349 × 1011，从下侧居中 (606,1440) 切到右对齐 (1211,1440)，再居中 (606,1440)。两次提交均 CGError 0，重新读取一致；最终回到本次测试前位置。界面检查确认屏幕选择、对齐选项、应用按钮、结果和诊断日志分区清楚。

重启普通版后，随航目标和居中选项自动载入，日志仅有屏幕读取，没有配置提交；确认重启不会自动移动屏幕。
